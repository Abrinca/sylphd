# GlobDB r232 evaluation: scripts

The scripts behind [the evaluation page](../../../docs/project/globdb-evaluation.md) (GTDB r232 vs
GlobDB r232). Nothing here depends on a particular machine: databases, metadata and samples are
passed through environment variables, with the defaults listed in each script's header. Run
everything from the repository root of a checkout (`uv sync` done) unless noted. Raw output (JSON,
sketches, reads) is not committed; it is regenerated by these scripts.

| Directory | What it does | Needs |
|---|---|---|
| `compare/run.sh` | profile pre-made sketches against one main database + UHGV + RefSeq fungi (the per-dataset table) | the databases, a metadata database, sketches |
| `ani/run.sh`, `ani/analyse.py` | the minimum-ANI sweep, 90–95: `ani_sweep.tsv` and four plots | as above, plus `matplotlib` for `analyse.py` |
| `parity/run.sh`, `parity/compare.py` | stock sylph + sylph-tax against sylphd on one database | `sylph` 1.0.0, `sylph-tax` 1.9.2, the reads |
| `ram-bench/` | memory under cgroup limits (`bench.py`, `run_ladder.sh`, `analyse.py`, `plot.py`) and the gut-metagenome samples (`fetch_reads.sh`, `prepare_reads.sh`, `make_sketches.py`) | rootless podman with cgroup v2, `fincore`, the databases |

All scripts accept `SYLPHD` (the command, default `sylphd`; use `SYLPHD="uv run sylphd"` in a
checkout) where they call it.

## Databases and metadata

Defaults, relative to the working directory:

```
db/gtdb-r232-c200-dbv2.syl2db
db/globdb_r232_sylph_v2_c200.syl2db
db/uhgv_c200_dbv1.syldb
db/fungi-refseq-2025-10-11-c200-dbv1.syldb
db/meta.sqlite            # a metadata database with both GTDB_r232 and GlobDB_r232 sources
```

Override with `DB_DIR`, `GTDB_DB`, `GLOBDB_DB`, `UHGV`, `FUNGI` and `META` (`compare/` and `ani/`),
`DB` and `META` (`parity/`), or `SYLPHD_DB_DIR`, `DB_GTDB`, `DB_GLOBDB`, `DB_UHGV`, `DB_FUNGI`
(`ram-bench/`). How to build the databases and the metadata is in `sylphd setup --help` and
the [Metadata database](../../../docs/reference/metadata.md) reference.

## Samples

Sketch every sample once with the databases' parameters (c = 200, k = 31), then reuse the sketches:

```bash
uv run python -I scripts/benchmarks/globdb/ram-bench/make_sketches.py sketches \
    soil_ERR17228984:reads/ERR17228984.fastq.gz \
    ocean:reads/SRR36700019_1.fastq.gz+reads/SRR36700019_2.fastq.gz
```

The gut metagenome (ENA DRR1003640) used for `gut`, `gut1M` and `gut250k` comes from
`ram-bench/fetch_reads.sh` and `prepare_reads.sh` (output under `$RAMBENCH_WORK`, default
`ram-bench-work/`). The other accessions are on the evaluation page; download them from ENA.

## Rerun

```bash
B=scripts/benchmarks/globdb

# 1. Per-dataset comparison (GTDB vs GlobDB at the default 95 % minimum ANI)
SKDIR=sketches META=db/meta.sqlite OUT=out/compare SYLPHD="uv run sylphd" \
    $B/compare/run.sh gtdb   db/gtdb-r232-c200-dbv2.syl2db
SKDIR=sketches META=db/meta.sqlite OUT=out/compare SYLPHD="uv run sylphd" \
    $B/compare/run.sh globdb db/globdb_r232_sylph_v2_c200.syl2db
# Classified share per source = sum of Sequence_abundance per tax_source in out/compare/*/<sample>.json.

# 2. Minimum-ANI sweep, 90–95
SKDIR=sketches OUT=out/ani ANIS="95 94 93 92 91 90" SYLPHD="uv run sylphd" $B/ani/run.sh
uv run --no-project --with matplotlib python -I $B/ani/analyse.py out/ani
#   -> out/ani/ani_sweep.tsv and four PNGs. The SAMPLES table at the top of analyse.py maps sample
#      names to labels; edit it for your own samples.

# 3. Parity with stock sylph + sylph-tax (reads in reads/, see the header of parity/run.sh)
OUT=out/parity READS=reads SYLPHD="uv run sylphd" $B/parity/run.sh
python -I $B/parity/compare.py out/parity

# 4. Memory under limits (rootless podman, one server at a time, 12–20 min per ladder)
export RAMBENCH_WORK=ram-bench-work       # results, logs, data/sketches/*.sylsp
$B/ram-bench/run_ladder.sh globdb         # or: trio (GTDB + UHGV + fungi)
$B/ram-bench/run_ladder.sh globdb 7.25 7.5   # specific limits (FORCE=1 to redo)
uv run python -I $B/ram-bench/plot.py globdb
```

`ram-bench/bench.py CONFIG LIMIT` runs one server under one limit (GiB or `unlimited`); its header
documents the phases (startup, cold, warm sequential, warm with two requests in flight) and the
environment variables: `RAMBENCH_WORK`, `SYLPHD_DB_DIR`, `SYLPHD_SRC` (the sylphd source tree that
is mounted read-only into the container; default: this checkout), `SYLPHD_VENV_LIB`
(its `site-packages`; default `.venv/lib/python3.14/site-packages`), `RAMBENCH_SKETCHES`,
`RAMBENCH_IMAGE`. The sketches used for the memory benchmark are the `*.sylsp` files in
`$RAMBENCH_WORK/data/sketches/`. Containers are named `ramb-*`; remove leftovers with
`podman rm -f $(podman ps -aq --filter name=ramb-)`.
